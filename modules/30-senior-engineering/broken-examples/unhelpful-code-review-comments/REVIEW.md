# Code Review: Pull Request Review Practice & Mentorship

## Scenario
A senior engineer on your team reviewed a pull request submitted by a junior backend engineer (`pr-review-comments.md`). The review sparked tension on the team: the junior engineer feels demoralized, while the senior engineer claims they are "just upholding code standards".

You examine both the code diff under review and the submitted comments.

## Review Objectives
1. Identify the severe technical vulnerabilities, reliability hazards, and architectural flaws in the code diff that the reviewer completely overlooked while bikeshedding.
2. Analyze the psychological, cultural, and communication anti-patterns in the reviewer's feedback.
3. Rewrite the code review into an exemplary, constructive review using the **Conventional Comments** specification (`blocking:`, `nit:`, `suggestion:`, `question:`). The review must firmly catch critical security and reliability blockers while mentoring the author with kindness, technical clarity, and code examples.
